벤치 3 · 개념 대비

GET은 읽기, POST는 쓰기

DART 실습은 전부 GET입니다. 이 벤치는 GET과 POST의 차이를 보여주는 개념 대비이며, 실제 요청은 전송되지 않습니다.

요청 (Request)
GET /watchlist?stock=005930 HTTP/1.1 Host: contest-server.example
응답 (Response)
200 OK {"stock": "005930", "name": "삼성전자"}
← 덱으로 돌아가기 (§200 GET·POST 두 동작)

벤치 5 · 단계별 시연

요청 한 번에 번거로움 네 단계가 숨어 있다

버튼을 눌러 학생 코드 → OpenDART API → 금감원 DB로 이어지는 요청-응답을 한 단계씩 확인합니다. 실제로 전송하지 않으며, 각 단계는 §300의 고통 ①~④와 그대로 대응합니다.

학생 코드
→
OpenDART API
→
금감원 DB
대기 중
"다음 단계"를 눌러 ①부터 시작합니다.
① ② 요청 단계의 번거로움
  • ① 조립 — 4개 파라미터를 주소에 손으로 채운다
  • ② 탐색 — 30행 중 '당기순이익(손실)' 행을 눈으로 찾는다
③ ④ 응답 이후의 번거로움
  • ③ 변환 — 쉼표 문자열은 그대로 더할 수 없다
  • ④ 환산 — 원을 억원으로 나누지 않으면 지표가 뒤틀린다
← 덱으로 돌아가기 (§300 요청-응답과 번거로움 네 단계)
