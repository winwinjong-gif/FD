## §1 정렬과 체이닝

[[FD-02-400__indexing-filter|400]]에서 조건에 맞는 행을 걸러내는 법을 배웠다. 이번엔 그 필터를 정렬·컬럼 선택과 이어 붙인다.

```python
import pandas as pd

kospi = pd.read_csv('data/kospi_listing.csv', dtype={'Code': str})

(
    kospi[kospi['Sector'] == '전기전자']
    .sort_values('Marcap', ascending=False)
    [['Name', 'Marcap']]
    .head(5)
)

# 예상 출력:
#            Name            Marcap
#          삼성전자  1464492791304000
#         SK하이닉스  1178284184745000
#         삼성전자우   148839858156500
#          삼성전기   104571174400000
#     LG에너지솔루션    81315000000000
```

한 줄씩 읽으면 셋이 이어 붙은 것이다. `kospi[kospi['Sector'] == '전기전자']`가 전기전자 업종만 걸러내고, `.sort_values('Marcap', ascending=False)`가 시가총액 큰 순서로 그 결과를 다시 세우고, `[['Name', 'Marcap']]`이 볼 컬럼만 남긴다. 코드를 `.`으로 이어 붙이면 걸러내고, 세우고, 필요한 컬럼만 꺼내는 작업이 한 문장으로 읽힌다. 메서드 체이닝이다.

시가총액 전체 상위 10개만 볼 때도 있다. 이때는 필터 없이 정렬만 하고 자르면 된다.

```python
kospi.sort_values('Marcap', ascending=False)[['Name', 'Marcap']].head(10)
```

`sort_values('Marcap', ascending=False)`는 표 전체를 시가총액이 큰 순서로 다시 세운다. 정렬 뒤에 `head(10)`을 붙이면 상위 10개만 남는다. 이 두 동작을 하나로 줄인 단축이 `nlargest`다.

```python
kospi.nlargest(10, 'Marcap')[['Name', 'Marcap']]
```

`nlargest(10, 'Marcap')`은 "정렬하고 자르기"를 한 번에 한다. 실제 `kospi_listing.csv`로 이 코드를 돌리면 이렇게 나온다.

## §2 100번의 세 줄, 한 단어씩

[[FD-02-100__wow-hook|100]] 마지막에 이 세 줄을 보여줬다. "지금 이해하라고 보여주는 코드가 아니다"라고 했던 그 코드다.

```python
import FinanceDataReader as fdr
df = fdr.DataReader('005930', '2026-01-02', '2026-06-30')
df['Close'].pct_change()
```

이제 한 단어씩 뜯는다.

| 코드 한 줄 | 배운 노트 | 개념 |
|---|---|---|
| `import FinanceDataReader as fdr` | 110 | 외부 라이브러리를 `fdr`이라는 짧은 이름으로 불러온다 |
| `fdr.DataReader('005930', ...)` | 110 + 300 | 종목코드와 기간을 주면 날짜가 인덱스인 DataFrame이 돌아온다 |
| `df['Close']` | 300 | 대괄호로 컬럼 하나를 꺼내면 Series가 된다 |
| `.pct_change()` | 600 | Series에 붙여 일별 수익률을 계산한다 |

세 줄 중 앞의 셋은 이미 아는 이름이었다. 낯선 건 마지막 `.pct_change()` 하나뿐이다. 여기까지가 원환의 닫힘이다 — [[FD-02-100__wow-hook|100]]이 던진 코드를 600번이 그대로 받아 설명했다.

## §3 왜 가격으로는 비교가 안 되나

삼성전자가 하루에 1,000원 오르는 것과 NAVER가 하루에 1,000원 오르는 것은 같은 일이 아니다. 삼성전자는 6만원대, NAVER는 38만원대다. 같은 1,000원이라도 출발점이 다르면 크기가 다르다.

손으로 먼저 짚어본다.

| 종목 | 어제 종가 | 오늘 종가 | 절대 변화 | 수익률 |
|---|---|---|---|---|
| A | 50,000 | 51,000 | +1,000 | +2.0% |
| B | 380,000 | 381,000 | +1,000 | +0.26% |

절대 변화는 똑같이 1,000원인데 수익률은 여덟 배 가까이 차이 난다. 가격이 다른 두 종목을 같은 자로 잴 수 없다는 게 여기서 눈에 보인다.

실제 데이터로 봐도 같다. 삼성전자는 1월 8일 61,100원에서 1월 9일 62,100원으로 올랐다 — 1,000원, +1.64%. 같은 기간 NAVER는 383,400원에서 387,400원으로 올랐다 — 4,000원, +1.04%. 절대 변화는 NAVER가 네 배 더 크지만, 수익률로 보면 삼성전자가 더 크게 움직였다.

단위가 다른 것을 하나의 자로 재는 방법이 수익률이다.

## §4 어제 값을 오늘 행으로 — `shift(1)`

`pct_change()`를 바로 쓰기 전에, 그 계산이 뭘 하는지부터 눈으로 본다. `shift(1)`은 한 칸 밀린 값을 옆 컬럼에 놓는다.

```python
samsung = pd.read_csv('data/samsung_005930.csv', index_col='Date')
samsung['Close_어제'] = samsung['Close'].shift(1)
samsung[['Close', 'Close_어제']].head()
```

| Date | Close | Close_어제 |
|---|---|---|
| 2026-01-02 | 62,000 | NaN |
| 2026-01-05 | 61,800 | 62,000 |
| 2026-01-06 | 61,600 | 61,800 |
| 2026-01-07 | 60,900 | 61,600 |
| 2026-01-08 | 61,100 | 60,900 |

`Close_어제` 컬럼은 `Close`를 그대로 한 칸 아래로 민 값이다. 첫 행만 빈 자리다 — 1월 2일에는 "어제"가 없다. 다음 절에서 만날 NaN이 여기서 미리 설명된다.

## §5 `pct_change()` — 수익률 표 완성

수익률은 (오늘 종가 − 어제 종가) / 어제 종가다. `Close`와 `Close_어제` 두 컬럼이 있으면 이 계산을 직접 쓸 수 있지만, pandas는 이미 함수로 준비해뒀다.

```python
samsung['Return'] = samsung['Close'].pct_change()
samsung[['Close', 'Return']].head(6)
```

| Date | Close | Return |
|---|---|---|
| 2026-01-02 | 62,000 | NaN |
| 2026-01-05 | 61,800 | -0.003226 |
| 2026-01-06 | 61,600 | -0.003236 |
| 2026-01-07 | 60,900 | -0.011364 |
| 2026-01-08 | 61,100 | 0.003284 |
| 2026-01-09 | 62,100 | 0.016367 |

첫 행 `Return`이 NaN인 건 오류가 아니라 사실이다. 1월 2일 앞에는 전날이 없으니 변화율 자체가 없다. **이 NaN을 0으로 채우지 않는다** — 채우면 실제로는 존재하지 않는 관측치를 하나 지어내는 셈이다. 이후 날짜들의 `pct_change()` 값이나 그 뒤로 이어 붙이는 누적곱(`(1+r).cumprod()`) 자체는 바뀌지 않는다 — 0을 곱하는 게 아니라 `1 + 0`을 곱하는 것이라 결과에 영향이 없다. 문제는 다른 데 있다: 없던 "1월 2일 수익률 0%"라는 관측치가 하나 늘어나면, 평균이나 표준편차 같은 통계는 실제보다 변동성을 낮게, 평균을 0 쪽으로 왜곡해서 보여준다. NaN인 채로 두거나 그 행을 떨어뜨리는 쪽이 맞다.

`pct_change()`가 계산하는 값은 단순수익률이다. 로그수익률과의 차이는 [[FD-01-900__hello-finance|W01]]에서 이미 다뤘다 — 여기서는 다시 유도하지 않고 링크만 건다.

같은 계산을 NAVER에도 그대로 적용하면 두 종목의 수익률을 나란히 비교할 수 있다.

```python
naver = pd.read_csv('data/naver_035420.csv', index_col='Date')
naver['Return'] = naver['Close'].pct_change()
naver[['Close', 'Return']].head(6)

# 예상 출력:
#              Close    Return
# Date
# 2026-01-02  379000       NaN
# 2026-01-05  380700  0.004485
# 2026-01-06  384700  0.010507
# 2026-01-07  383700 -0.002599
# 2026-01-08  383400 -0.000782
# 2026-01-09  387400  0.010433
```

가격 표로는 삼성전자(6만원대)와 NAVER(38만원대)를 나란히 놓고 비교할 수 없었다. `Return` 컬럼은 둘 다 같은 자 — 퍼센트 — 위에 있어서, 두 종목을 곧바로 나란히 놓고 어느 쪽이 더 크게 움직였는지 말할 수 있다.

> [!tip] 💬 스스로 확인해 보세요
> 1. 위 NAVER 표와 앞서 만든 삼성전자 `Return` 표를 같은 날짜끼리 비교하면, 1월 6일에는 어느 종목이 더 크게 움직였는가?

실습에서는 이 흐름을 그대로 다시 짠다 — 정렬·체이닝부터 `shift`를 거쳐 `pct_change()`로 수익률 표를 완성하는 순서다.

## §6 마무리 — 어디에 쓰나

오늘 만든 수익률 표는 기말 포트폴리오 프로젝트의 첫 조각이다. 12주차에 이 표를 다시 꺼내 쓴다.

증권사·자산운용사 신입이 입사 첫 달에 하는 일이 정확히 이것이다 — 데이터를 받아서 표로 정리하는 일. 화려해 보이지 않아도 그 뒤의 모든 분석이 이 표 위에 선다. Copilot에게 코드를 대신 쓰게 해도, `df`가 뭔지 `Series`가 뭔지 `loc`이 뭘 하는지 모르면 나온 코드가 맞는지 스스로 판단할 수 없다.
