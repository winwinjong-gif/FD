## 데이터를 가져온다

> [!info] 학습 목표
>
> - FinanceDataReader로 상장종목 목록과 특정 종목의 기간별 주가를 가져온다.
> - `DataReader`가 돌려주는 표의 컬럼(OHLCV)이 각각 무엇을 뜻하는지 안다.
> - 종목코드를 왜 항상 문자열로 다뤄야 하는지 설명한다.

## §1 번거로움을 한 줄로 줄인다

네이버 금융, 야후 파이낸스, 한국거래소(KRX) 어디를 가든 원하는 종목의 가격을 볼 수는 있다. 문제는 그다음이다. 그 표를 엑셀로 받아서, 원하는 기간만 자르고, 여러 종목을 나란히 놓으려면 매번 손으로 다운로드하고 붙여넣어야 한다. 종목 하나면 참을 만하다. [[FD-02-100__wow-hook|100]]에서 본 것처럼 950개가 되는 순간 이 방식은 무너진다.

FinanceDataReader(이하 FDR)는 이 과정을 몇 줄로 줄인 라이브러리다. 여러 출처의 금융 데이터를 모아 pandas가 바로 다룰 수 있는 형태로 돌려준다.

> [!tip]- FDR은 어디서 왔나
> - pandas가 표 하나를 다루는 도구라면, FDR은 그 표를 채워 넣는 도구다.
> - 미국 시장 중심의 기존 라이브러리들이 국내 데이터를 제대로 다루지 못하던 자리를 메우기 위해 만들어진 오픈소스 프로젝트다.
> - KRX 상장종목·지수·환율·암호화폐까지 하나의 호출 방식으로 통일해서 돌려준다.
> - 공식 가이드: [FinanceDataReader Users Guide](https://financedata.github.io/posts/finance-data-reader-users-guide.html)

> [!tip]- 자주 쓰는 함수
> | 함수 | 무엇을 반환하나 |
> |---|---|
> | `fdr.DataReader(code, start, end)` | 종목/지수/환율의 기간별 시계열 |
> | `fdr.StockListing(market)` | 상장종목 목록 |
> | `fdr.StockListing('KRX')` | 코스피+코스닥 전체 목록 |
> | `fdr.DataReader('KS11', start, end)` | KOSPI 지수 시계열 |
> | `fdr.DataReader('USD/KRW', start, end)` | 원/달러 환율 |
> | `fdr.DataReader('BTC/KRW', start, end)` | 암호화폐 시세 |
>
> 이번 학기에서는 굵게 쓴 두 개, `DataReader`와 `StockListing`만 쓴다. 나머지는 이런 것도 된다는 정도로만 알아 둔다.

설치는 W01에서 이미 끝냈다. 여기서는 불러오는 한 줄만 다시 본다.

```python
import FinanceDataReader as fdr
```

[[FD-02-100__wow-hook|100]]에서 던진 세 줄 중 첫 줄이 바로 이것이다. `fdr`이라는 짧은 이름으로 불러온 이유는 매번 `FinanceDataReader.DataReader(...)`라고 치기 싫어서다.

## §2 종목 목록 — StockListing

실제로는 이렇게 받는다 — 다만 이 줄은 오늘 실행하지 않는다.

```python
# 실제로는 이렇게 받는다 — 이 줄은 실행하지 않는다
# fdr.StockListing('KOSPI')
```

호출 하나로 KOSPI 상장종목 950여 행이 돌아온다. 컬럼이 여러 개 딸려 오지만, 지금 눈여겨볼 것은 `Code`, `Name`, `Marcap` 세 개다 — 종목코드, 종목명, 시가총액.

이 줄을 수업에서 실행하지 않는 이유는 세 가지다. 매번 다른 값이 돌아와 채점이 안 되고, 네트워크가 막힌 강의실에서는 애초에 실행이 안 되고, 무엇보다 오늘 배우는 건 표를 "읽는" 방법이지 "받는" 방법의 세부가 아니기 때문이다. 그래서 수업에서는 오늘 아침 떠 둔 스냅샷을 CSV로 읽는다.

```python
import pandas as pd

kospi = pd.read_csv('data/kospi_listing.csv', dtype={'Code': str})
kospi.head(3)

# 예상 출력:
#      Code    Name Market Sector            Marcap
# 0  005930    삼성전자  KOSPI   전기전자  1464492791304000
# 1  000660  SK하이닉스  KOSPI   전기전자  1178284184745000
# 2  005935   삼성전자우  KOSPI   전기전자   148839858156500
```

이 CSV는 40개 종목만 담았다 — 950개 전부를 수업용으로 들고 다닐 필요가 없어서 상위권만 추렸다. 컬럼도 실제 FDR보다 적다: `Code`, `Name`, `Market`, `Sector`, `Marcap` 다섯 개뿐이다. `Sector`(업종)는 FDR이 기본으로 주는 컬럼이 아니라 수업용으로 단순하게 붙인 값이다 — 실제 업종 분류표를 그대로 신뢰하지 않는다.

## §3 주가 — DataReader와 OHLCV

특정 종목의 기간별 시세는 `DataReader`로 받는다.

```python
# 실제로는 이렇게 받는다 — 이 줄은 실행하지 않는다
# fdr.DataReader('005930', '2026-01-02', '2026-06-30')
```

역시 라이브 호출은 실행하지 않는다. 대신 같은 기간을 담은 고정 CSV를 읽는다.

```python
samsung = pd.read_csv(
    'data/samsung_005930.csv',
    index_col='Date',
    parse_dates=True,
)
samsung.shape

# 예상 출력:
# (120, 6)
```

```python
samsung.head(3)

# 예상 출력:
#              Open   High    Low  Close    Volume    Change
# Date
# 2026-01-02  61900  62400  61400  62000  40702881  0.012900
# 2026-01-05  61800  62100  61600  61800  12673757 -0.003226
# 2026-01-06  62100  62500  61500  61600  38557870 -0.003236
```

받은 표를 바로 계산에 쓰지 않는다. `shape`으로 크기를 먼저 확인하고 `head(3)`으로 값을 눈으로 본다 — 120행 6열이라는 것, 인덱스가 날짜라는 것, 첫 며칠의 가격이 말이 되는 범위인지. 이 습관은 [[FD-02-300__dataframe|300]]에서 탐색 3종 세트로 정식화된다.

컬럼 여섯 개는 각각 다른 것을 말한다.

| 컬럼 | 뜻 |
|---|---|
| `Open` | 시가 — 그날 처음 거래된 가격 |
| `High` | 고가 — 그날 가장 높았던 가격 |
| `Low` | 저가 — 그날 가장 낮았던 가격 |
| `Close` | 종가 — 그날 마지막 거래 가격 |
| `Volume` | 거래량 — 그날 거래된 주식 수 |
| `Change` | 전일 대비 등락률 |

가격을 하나만 봐야 한다면 `Close`를 본다. 하루가 끝난 뒤의 값이라 다음 날 시가와 이어지고, [[FD-02-600__returns-pipeline|600]]에서 만들 수익률 표도 이 컬럼에서 출발한다. `Change`가 이미 등락률을 갖고 있는데도 [[FD-02-600__returns-pipeline|600]]에서 직접 계산하는 이유는, FDR이 주는 값을 그대로 믿기보다 `pct_change()`가 같은 값을 만들어낸다는 걸 스스로 확인하기 위해서다. 다만 표를 일부만 잘라서 읽으면 완전히 같지는 않다 — 잘린 구간의 첫 행은 그 앞의 종가를 모르니 `pct_change()`가 NaN을 준다. `Change`는 원래 표 전체를 기준으로 이미 계산되어 있어 그 자리에 값이 남아 있을 수 있다. 두 값이 정확히 일치하는 건 잘린 구간의 두 번째 행부터다.

## §4 종목코드는 문자열이다

방금 읽은 두 표 모두 종목코드가 `005930`처럼 0으로 시작한다. 이게 왜 문제가 될까.

```python
# dtype 없이 읽으면 무슨 일이 생기는지
wrong = pd.read_csv('data/kospi_listing.csv')
wrong['Code'].head(3)

# 예상 출력:
# 0      5930
# 1       660
# 2    5935
# Name: Code, dtype: int64
```

pandas는 `Code` 컬럼을 숫자로만 이루어진 것으로 보고 자동으로 정수형으로 읽는다. 정수에서는 앞자리 0이 의미가 없으니 그냥 버려진다. `005930`이 `5930`이 되는 순간, 이 값으로 삼성전자를 다시 찾을 방법이 없다 — 조회하면 다른 종목이거나 아예 없는 코드다.

> [!warning] 종목코드는 계산 대상이 아니다
> - `'005930'`은 되고 `5930`은 안 된다.
> - 종목코드는 숫자처럼 생겼지만 더하거나 곱할 대상이 아니라 이름표다 — 전화번호나 우편번호처럼, 앞자리를 없애면 다른 것이 되어버리는 식별자다.
> - 그래서 읽을 때부터 `dtype={'Code': str}`로 문자열임을 못 박는다.

앞서 CSV를 읽을 때 이미 `dtype={'Code': str}`를 넣었던 이유가 이것이다. [[FD-02-200__series|200]]에서 종목코드를 인덱스로 쓰는 Series를 만들 때도 같은 규칙이 그대로 적용된다.
