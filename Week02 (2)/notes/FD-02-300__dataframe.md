## 📊 엑셀 시트 한 장 — DataFrame

> [!info] 학습 목표
>
> - Series 여러 개를 왜 하나로 묶어야 하는지 설명한다
> - 딕셔너리로 DataFrame을 두 가지 방식(컬럼 중심·행 중심)으로 만든다
> - 표를 받으면 `shape`→`columns`→`dtypes`→`head(3)` 순서로 확인하는 습관을 몸에 익힌다
> - `df['컬럼']`이 Series가 되고 `df[['컬럼', ...]]`이 DataFrame으로 남는 이유를 구분한다

---

#### §1 🧩 Series 하나로는 부족하다

[[FD-02-200__series|200]]에서 종가를 Series로 만들었다. 이번엔 종목 하나가 아니라 KOSPI 상장종목 40개를 다룬다고 하자. 종가 Series 하나, 거래량 Series 하나, 시가총액 Series 하나 — 이렇게 따로 들고 다니면 어떤 문제가 생기나.

세 Series를 각각 인덱스로 정렬하고, 삼성전자 행이 어디 있는지 세 번 찾고, 값이 하나 바뀌면 세 곳을 따로 고쳐야 한다. 같은 종목의 값인데 흩어져 있으니 같이 쓰기가 불편하다.

이 세 Series를 옆으로 나란히 붙인 것이 DataFrame이다. 붙이고 나면 종목 하나를 찾을 때 한 번만 찾으면 되고, 그 행에 종가·거래량·시가총액이 나란히 있다.

개념 모델은 엑셀 시트 한 장이다. 행은 종목, 열은 속성, 칸은 값 — 이 세 가지만 있으면 DataFrame을 그릴 수 있다.

|     | 열 1 (`Code`) | 열 2 (`Name`) | 열 3 (`Marcap`)        |
| --- | ------------ | ------------ | --------------------- |
| 행 0 | `'005930'`   | 삼성전자         | 1,464,492,791,304,000 |
| 행 1 | `'000660'`   | SK하이닉스       | 1,178,284,184,745,000 |
| 행 2 | `'005935'`   | 삼성전자우        | 148,839,858,156,500   |

행은 종목이고 열은 속성이다. 이 표가 오늘 다룰 KOSPI 상장종목 데이터의 실제 첫 세 줄이다.

#### §2 🔨 만들기 — 컬럼 중심과 행 중심

DataFrame을 손으로 만드는 방법은 두 가지다. 데이터가 어느 방향으로 들어오느냐에 따라 편한 쪽이 다르다.

**컬럼 중심** — 컬럼 이름을 키로, 값 리스트를 값으로 넣는다.

```python
import pandas as pd

# 컬럼 이름 -> 값 리스트, 컬럼 단위로 데이터를 갖고 있을 때 편하다
data_컬럼중심 = {
    'ticker': ['005930', '000660', '005935'],
    'Marcap': [1464492791304000, 1178284184745000, 148839858156500],
}
df1 = pd.DataFrame(data_컬럼중심)
```

**행 중심** — 행 하나를 딕셔너리 하나로 표현하고, 그 딕셔너리들을 리스트로 묶는다.

```python
# 행 하나 = 딕셔너리 하나, 레코드 단위로 데이터를 받을 때(API 응답 등) 편하다
data_행중심 = [
    {'ticker': '005930', 'Marcap': 1464492791304000},
    {'ticker': '000660', 'Marcap': 1178284184745000},
    {'ticker': '005935', 'Marcap': 148839858156500},
]
df2 = pd.DataFrame(data_행중심)
```

두 코드가 만드는 DataFrame은 같다. `df1`과 `df2`를 나란히 찍어보면 값도 순서도 똑같다. 컬럼 단위로 생각하느냐 레코드 단위로 생각하느냐의 차이일 뿐, 도착지는 하나다.

#### §3 🔍 표를 받으면 가장 먼저 하는 세 가지

FinanceDataReader가 돌려준 표든, 다른 사람이 준 CSV든 — 받자마자 코드부터 쓰지 않는다. 먼저 표의 생김새를 확인한다.

```python
import pandas as pd

# 실습 노트북과 같은 고정 CSV, 종목코드 선행 0을 지키려면 dtype 지정이 필수다
df = pd.read_csv('data/kospi_listing.csv', dtype={'Code': str})

print(df.shape)
# (40, 5)

print(df.columns)
# Index(['Code', 'Name', 'Market', 'Sector', 'Marcap'], dtype='str')

print(df.dtypes)
# Code        str
# Name        str
# Market      str
# Sector      str
# Marcap    int64
# dtype: object

print(df.head(3))
#      Code    Name Market Sector            Marcap
# 0  005930    삼성전자  KOSPI   전기전자  1464492791304000
# 1  000660  SK하이닉스  KOSPI   전기전자  1178284184745000
# 2  005935   삼성전자우  KOSPI   전기전자   148839858156500
```

`shape`이 `(40, 5)`라고 알려준다 — 40개 종목, 5개 속성. 눈으로 보지 않아도 크기를 안다. `columns`는 이 표에서 쓸 수 있는 열 이름 목록이고, `dtypes`는 각 열이 문자인지 숫자인지 알려준다. `Code`가 `str`(문자열)로 잡힌 이유는 `dtype={'Code': str}`을 지정했기 때문이다 — 지정하지 않으면 `'005930'`의 앞자리 0이 사라진다. `Marcap`은 `int64`, 계산 가능한 숫자다.

`shape`→`columns`→`dtypes` 세 줄을 찍은 다음에야 `head(3)`으로 실제 값을 본다. 순서를 지키는 이유는 간단하다 — 크기와 타입을 먼저 알아야 head로 본 세 줄이 표 전체를 대표하는지 판단할 수 있다.

| 메서드 | 반환하는 것 | 무엇을 판단하나 |
|---|---|---|
| `df.shape` | `(행, 열)` 튜플 | 표가 몇 개짜리인가 |
| `df.columns` | 열 이름 목록 | 어떤 속성을 쓸 수 있나 |
| `df.dtypes` | 열별 타입 | 계산 가능한 열인가, 텍스트인가 |
| `df.head(3)` | 앞 3행 표 | 실제 값이 기대한 모양인가 |

이 습관은 오늘 하루만 쓰고 버리는 게 아니다. 이 과목 나머지 10주 내내 새 표를 받을 때마다 반복한다. 데이터를 안 보고 코드부터 쓰면, 나중에 결과가 이상해도 어디서부터 틀렸는지 못 찾는다.

> `FD-02-800__dataframe-explore`에서 이 세 줄을 KOSPI 40개 종목 CSV에 직접 실행하고, `shape`이 왜 `(40, 5)`인지 손으로 확인한다.

#### §4 🎯 컬럼을 꺼내면 Series가 된다

DataFrame에서 컬럼 하나를 대괄호로 꺼내면 무엇이 나올까.

```python
print(type(df['Marcap']))
# <class 'pandas.Series'>

print(type(df[['Name', 'Marcap']]))
# <class 'pandas.DataFrame'>
```

`df['Marcap']`은 Series다. `df[['Name', 'Marcap']]`은 DataFrame이다. 대괄호 안에 문자열 하나만 넣느냐, 리스트로 감싸서 넣느냐 — 이 차이 하나로 타입이 갈린다.

이 연결이 [[FD-02-200__series|200]]과 300번을 하나로 만든다. DataFrame은 Series 여러 개를 옆으로 붙인 것이었으니, 거꾸로 하나를 뽑아내면 다시 Series로 돌아간다.

```python
print(df['Marcap'].mean())
# 108527194534476.25
```

[[FD-02-200__series|200]]에서 배운 `.mean()`이 `df['Marcap']`에도 그대로 듣는다. 새 메서드를 배우는 게 아니라, DataFrame에서 Series 하나를 꺼내 이미 아는 것을 그대로 쓴 것이다. `df.mean()`이 따로 있고 `s.mean()`이 따로 있는 게 아니라, `df['Marcap']`이 Series가 되는 순간 Series의 메서드가 전부 따라온다.

대괄호 하나로 문법이 갈리는 이 지점이 이번에 처음 등장하는 문법 의존이다. 낯설면 실습 노트북의 접힘 블록이 딕셔너리·리스트 접근을 다시 짚어준다 — 여기서는 이 정도만 알고 넘어가도 된다.

> [!tip] 실습에서
> `FD-02-800__dataframe-explore`에서 `df['Marcap']`과 `df[['Name', 'Marcap']]`을 각각 찍어 `type()`으로 차이를 확인하고, `df['Marcap'].mean()`을 직접 계산한다.
