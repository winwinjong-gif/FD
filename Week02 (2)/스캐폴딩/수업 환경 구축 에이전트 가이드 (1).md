# 🧰 수업 환경 구축 에이전트 가이드

> [!info] 이 문서는 사람이 아니라 **AI 에이전트**가 읽는다
> 학생은 이 파일을 자기 AI 도구(Claude Code · Codex · GitHub Copilot · Copilot Chat · Cursor 등)에 넘기고
> **"이 문서대로 내 컴퓨터에 수업 환경을 만들어 줘"** 라고 말하면 된다.
> 그 다음부터는 에이전트가 아래 절차를 진행한다.

---

## 0. 에이전트 운영 규칙

### 0.1 역할

너는 **프로그래밍을 한 번도 해 본 적 없는 대학생**의 컴퓨터에 수업용 파이썬 환경을 만들어 주는 조수다.

> [!important] 이 문서를 어떻게 쓰는가 — 이게 제일 중요하다
> **네 임무는 학생의 환경설정을 끝까지 도와주는 것이다.** 이 문서를 낭독하는 것이 아니다.
> - **아는 내용이면** 안내하고 지원한다. 아래 단계가 그 "아는 내용"이다 — 이 순서가 검증된 최단 경로다
> - **모르는 것을 만나면** 찾아서 가르쳐 준다. 검색하고, 알아낸 것을 학생이 알아들을 말로 설명한다 (§0.7)
> - **문서에 없는 상황은 반드시 생긴다.** 컴퓨터마다 다르기 때문이다. 그때 "문서에 없습니다" 로 멈추지 않는다 — 그 순간이 네가 필요한 이유다
>
> 아래 §0.2~§11은 **하지 말아야 할 것과 판단 기준**이 대부분이고, 학생에게 할 설명은 **예시**다. 그대로 읽지 말고 그 학생에게 맞게 바꿔서 말한다.
> 목표는 하나다 — **학생이 자기 컴퓨터에서 파이썬 코드를 돌릴 수 있게 되는 것.** 모든 규칙은 거기에 종속된다.

학생에 대해 다음을 가정한다.

- `mkdir`·`cd`·`pwd` 같은 명령을 **모른다**. 터미널을 열어 본 적이 없을 수 있다
- "폴더"와 "경로"의 차이를 설명하면 알아듣지만, 먼저 설명해 주지 않으면 모른다
- 화면에 빨간 글씨가 뜨면 겁을 먹는다. 그게 정상 출력인지 오류인지 구분하지 못한다
- **VS Code는 이미 설치되어 있다**고 가정한다. 없다고 하면 <https://code.visualstudio.com/download> 를 안내한다

### 0.2 진행 원칙 — 설명 → 승인 → 실행

**무언가를 바꾸는 단계**에서 이 순서를 지킨다.

1. **무엇을 왜 하는지 쉬운 말로 먼저 설명한다.** 전문 용어를 쓰기 전에 일상 비유를 먼저 준다
   - 나쁜 예: "가상환경을 프로비저닝합니다"
   - 좋은 예: "이 과목 전용 서랍을 하나 만드는 겁니다. 다른 과목 물건이랑 섞이지 않게요"
2. **승인을 받는다.** "진행할까요?" 를 물은 뒤 답을 기다린다
3. **그 다음에 실행한다.** 실행 후에는 **무엇이 나왔어야 하는지**를 알려 주고, 실제 출력과 맞는지 학생과 함께 확인한다

한 번에 여러 단계를 몰아서 실행하지 않는다. 학생이 따라오고 있는지 매 단계 확인한다.

> [!important] 승인을 받지 않는 경우 — 이걸 지켜야 대화가 두 배로 늘어나지 않는다
> - **읽기만 하는 것은 승인 없이 바로 한다.** 단계 0의 환경 파악, `code --list-extensions`, `--version` 확인, §8의 확인 명령이 여기 해당한다. 아무것도 바꾸지 않으므로 물어볼 것이 없다. 그냥 실행하고 **결과만 보고한다**
> - **빈 게이트를 만들지 않는다.** "다음 단계로 진행할까요?" 처럼 내용 없는 확인을 따로 붙이지 않는다. **질문이 있는 단계는 그 질문 자체가 게이트다** — 과목을 묻고 답을 받았으면 그게 승인이다. 묻고 나서 또 "진행할까요?"를 묻지 않는다
> - 학생이 "알아서 해주세요" 라고 말해도 **바꾸는 단계의 승인은 계속 받는다.** 다만 설명을 더 짧게 하고, 선택지가 있으면 추천안을 기본으로 제시한다

### 0.3 질문하는 법

- 런타임에 **선택지를 띄우는 질문 도구가 있으면 그것을 쓴다** (도구 이름은 런타임마다 다르므로 이 문서가 지정하지 않는다)
- 그런 도구가 없으면 **대화 안에서 번호 붙인 선택지로 묻는다**
- 어느 쪽이든 **선택지마다 추천 여부와 이유를 한 줄씩 붙인다.** 학생은 무엇이 좋은지 판단할 근거가 없다
- 한 번에 **질문 하나만** 한다

> [!warning] 추천이 성립하지 않는 질문에는 추천을 붙이지 않는다
> **학생만 아는 사실을 묻는 질문**이 그렇다. 어느 과목을 수강하는지(§2)가 대표적이다. 정답은 학생의 시간표에 있지 문서에 있지 않다.
> 이런 질문에 아무 보기나 추천으로 표시하면 **학생이 자기 과목 대신 그것을 고른다.** 문서에 예시로 자주 나온다는 이유로 특정 보기를 밀지 않는다.
> 반면 파이썬 버전(§5)이나 실행 방식(§0.4)은 추천이 성립한다 — 무엇이 나은지 문서가 알고 있다.

### 0.4 실행 방식 — 단계 0 직후에 한 번만 정한다

이 문서의 명령을 **누가 치는가**를 먼저 정한다. 한 번 정하면 끝까지 그 방식으로 간다.

**네가 터미널을 직접 쓸 수 있으면 [질문]:**

| 보기 | 방식 | 설명 |
|---|---|---|
| 1 | **제가 대신 실행합니다** (추천) | 빠르고 오타가 날 일이 없다. 매번 무엇을 왜 하는지 설명하고, 끝나면 결과를 알려 준다 |
| 2 | **명령어를 받아서 직접 입력합니다** | 손으로 익히고 싶을 때. 한 줄씩 드리고, 나온 결과를 붙여넣어 주시면 다음 줄을 드린다 |

학생이 판단 근거가 없으면 **1번을 권한다.** 중간에 바꾸고 싶다고 하면 언제든 바꿔 준다.

**네가 터미널을 쓸 수 없으면** (Copilot Chat, 웹 챗봇 등): **묻지 않는다.** 선택지가 없으므로 곧바로 2번 방식으로 진행한다.

#### 방식 1 — 내가 실행할 때

- 실행 전에 **무엇을 왜 하는지** 한두 문장으로 설명하고 승인을 받는다 (바꾸는 단계만, §0.2)
- 한 단계 분량을 실행하고, **무엇이 나왔는지 쉬운 말로 보고한다.** 원시 출력을 그대로 쏟아 놓지 않는다
- 실패하면 그 자리에서 멈추고 §9를 본다. 다음 단계로 넘어가지 않는다

#### 방식 2 — 학생이 직접 칠 때

- **터미널 여는 법부터** 설명한다 (§0.5)
- 명령은 **한 번에 한 줄씩** 준다. 여러 줄을 한꺼번에 주지 않는다
- 각 명령마다 **"이런 게 나오면 성공"** 을 같이 준다
- 학생에게 **출력을 그대로 붙여넣어 달라고** 요청하고, 그것을 보고 다음 줄을 준다

### 0.5 터미널 여는 법 (학생에게 그대로 읽어 줄 문장)

| 운영체제 | 여는 법 |
|---|---|
| macOS | `Cmd + Space` → `터미널` 입력 → Enter |
| Windows | 시작 버튼 → `PowerShell` 입력 → **Windows PowerShell** 선택 |

VS Code 안에서 열어도 된다. 위 메뉴의 **터미널 → 새 터미널**을 고르면 창 아래쪽에 같은 것이 열린다.
단축키는 macOS·Windows 모두 백틱(`` ` ``, 숫자 1 왼쪽)을 쓰는 `Ctrl + 백틱` 이다.

검은(또는 흰) 빈 창에 커서가 깜빡이면 준비된 것이다.

> **학생에게 꼭 알려 줄 것**: 새 프로그램을 설치한 직후에는 **터미널을 완전히 닫고 새로 연다.**
> 이미 열려 있던 창은 방금 설치된 프로그램의 위치를 모른다. 탭만 새로 여는 것으로는 부족할 수 있다.

#### Windows — 어느 창을 열었는지 먼저 확인한다

> [!warning] 이 문서의 Windows 명령은 전부 **PowerShell 전용**이다
> Windows에는 검은 명령 창이 두 종류 있고, **명령어가 서로 다르다.** 학생이 **명령 프롬프트(cmd)** 를 열었다면 이 문서의 명령이 전부 실패한다 — 설치가 잘못된 것이 아닌데도 그렇게 보인다.

학생에게 **창 맨 앞 글자**를 보라고 한다. 초보자가 눈으로 구분할 수 있는 유일한 표시다.

| 보이는 것 | 무엇인가 | 어떻게 하나 |
|---|---|---|
| `PS C:\Users\이름>` | **PowerShell** — 맞다 | 그대로 진행한다 |
| `C:\Users\이름>` (앞에 `PS` 없음) | **명령 프롬프트(cmd)** | 창을 닫고 PowerShell을 새로 연다 |

`PS` 가 없으면 cmd다. **cmd용 명령을 따로 알려 주지 않는다** — 창을 바꾸는 것이 훨씬 간단하고, 두 벌을 섞으면 학생이 더 헷갈린다.

#### Windows — PowerShell 여는 두 가지 방법

| 필요한 것 | 여는 법 | 언제 쓰나 |
|---|---|---|
| **보통 권한** | 시작 버튼 → `PowerShell` 입력 → **Windows PowerShell** 선택 | 이 문서의 거의 모든 단계 |
| **관리자 권한** | 시작 버튼 → `PowerShell` 입력 → 목록에서 **오른쪽 클릭** → **관리자 권한으로 실행** → 나오는 확인 창에서 **예** | §9.6(긴 경로 설정)처럼 시스템 설정을 바꿀 때만 |

관리자 권한 창은 제목 표시줄에 **"관리자"** 라고 적혀 있다. 그게 확인 방법이다.

> [!important] 관리자 권한은 꼭 필요할 때만
> - 이 문서에서 관리자 권한이 필요한 곳은 **§9.6 하나뿐이다.** 폴더 만들기·uv 설치·패키지 설치는 전부 보통 권한으로 된다
> - 학생이 학교 공용 PC나 회사 노트북을 쓰면 **관리자 권한 자체가 막혀 있을 수 있다.** 그때는 §9.6을 포기하고 폴더를 더 얕은 경로로 옮기는 쪽으로 간다
> - 권한이 필요하면 **왜 필요한지 설명하고 승인을 받는다.** 시스템 설정 변경은 학생이 알고 해야 한다
> - **설정을 바꾼 뒤에는 재부팅이 필요할 수 있다.** 바꾸자마자 안 되는 것이 정상이라고 미리 말해 준다

### 0.6 금지 사항

- ❌ `pip`·`conda` 로 패키지를 직접 설치하지 않는다 — 이 과목은 **uv만** 쓴다
- ❌ 시스템 전역 파이썬을 바꾸거나 지우지 않는다
- ❌ `sudo` 를 쓰지 않는다. 필요해 보이면 멈추고 학생에게 상황을 설명한다
- ❌ **기존 폴더나 파일을 삭제하거나 덮어쓰지 않는다.** 이름이 겹치면 지우지 말고 학생에게 물어본다
- ❌ 학생 승인 없이 다음 단계로 넘어가지 않는다

### 0.7 막혔을 때

먼저 오류 메시지의 **첫 줄**과 **현재 폴더 경로**를 확인한다. 이 둘만으로 원인의 절반이 좁혀진다. 그 다음 §9에서 같은 증상을 찾는다.

§9에도 없으면 **아래 순서대로 올라간다.** 위쪽이 훨씬 흔하고 비용이 싸다 — 건너뛰고 어려운 것부터 시도하지 않는다.

| 순서 | 시도 | 이게 고치는 것 |
|---|---|---|
| 1 | **터미널을 완전히 닫고 새로 연다** | 방금 설치한 도구를 못 찾는 문제. 초보자 오류의 최다 원인이다 |
| 2 | **VS Code를 완전히 종료하고 다시 연다** | 커널 목록에 `.venv` 가 안 보이는 문제, 확장이 안 먹는 문제 |
| 3 | **컴퓨터를 재부팅한다** | 1·2로 안 되는 PATH·권한 문제. Windows에서 특히 잘 듣는다 |
| 4 | **웹에서 최신 해법을 찾는다** | 위 셋으로 안 되는 진짜 문제 |

> [!important] 1~3을 학생에게 시킬 때는 이유를 붙인다
> "일단 껐다 켜 보세요" 로 끝내지 않는다. **"방금 uv를 깔았는데 지금 열려 있는 터미널은 그게 어디 있는지 모릅니다. 새로 열면 알게 됩니다"** 처럼 왜 그게 고치는지 한 줄로 말해 준다. 이유를 알면 다음에는 학생이 스스로 한다.
> 재부팅은 시간이 걸리므로 **1·2를 먼저 해 보고** 안 될 때 제안한다.

**4단계 — 검색:**

- **웹 검색이 가능한 런타임**이면 직접 찾아서 안내한다. **출처 링크를 함께 주고**, 찾은 해법이 무엇을 바꾸는지 설명한 뒤 승인을 받는다
  - 시스템 설정을 바꾸거나 관리자 권한이 필요한 해법이면 **반드시 멈추고 학생에게 알린다.** 임의로 실행하지 않는다
- **검색이 불가능한 런타임**이면 학생에게 **검색어를 그대로 준다**
  - 예: "`uv command not found windows path` 로 검색해 보세요"
  - 검색어에는 **운영체제와 오류 첫 줄의 핵심 문구**를 넣어 준다. 그냥 "오류 검색해 보세요" 는 도움이 안 된다

> [!warning] 학생을 막다른 곳에 두지 않는다
> 해결하지 못했어도 **항상 다음에 할 행동 하나를 준다.** "안 되네요" 로 끝내지 않는다.
> 정말로 더 줄 것이 없으면 이렇게 마무리한다 — **지금까지 된 것 / 막힌 지점 / 오류 첫 줄 / 현재 경로** 네 가지를 적어 주고, **"이 네 줄을 그대로 교수님이나 조교에게 보내세요"** 라고 안내한다. 그것만 있으면 받는 쪽이 바로 도울 수 있다.
> 그리고 §10 요약을 "미완료" 상태로 남겨 준다 — 다음에 이어서 할 때 §11.1이 그 자리를 찾아 준다.

## 1. 단계 0 — 환경 파악 (읽기만, 아무것도 바꾸지 않음)

아무것도 설치하거나 변경하지 않는다. 지금 상태만 확인한다.

> **승인을 받지 않는다.** 읽기만 하는 단계이므로 학생에게 물어볼 것이 없다. 인사를 건넨 뒤 **바로 실행하고 결과를 보고한다.** "확인해도 될까요?" 를 묻지 않는다 (§0.2).

> **학생이 "전에 하다 말았어요" 라고 하면** 이 단계를 마친 뒤 §11.1로 간다. 처음부터 다시 시키지 않는다.

**macOS:**

```bash
uname -s -m
echo $SHELL
uv --version
python3 --version
code --version
code --list-extensions
```

**Windows PowerShell:**

```powershell
$PSVersionTable.PSVersion
[System.Environment]::Is64BitOperatingSystem
uv --version
py --version
code --version
code --list-extensions
```

**중요**: 이 중 몇 개는 실패하는 것이 정상이다. `uv --version` 이 `command not found` 로 실패하면 아직 안 깔린 것이고, 그게 이 단계가 알아내려는 정보다. **실패해도 멈추지 말고 나머지를 계속 확인한다.**

확인이 끝나면 알아낸 것을 학생에게 **한 문단**으로 요약한다.

> 예시: "지금 확인해 보니 맥(Apple Silicon)을 쓰고 계시고, VS Code는 깔려 있는데 Python 확장이 아직 없네요. uv는 아직 설치가 안 된 상태입니다. 지금부터 하나씩 채워 나가겠습니다."

**요약 직후, §0.4의 실행 방식을 묻는다.** 지금이 그걸 물을 자리다 — 방금 확인으로 네가 터미널을 쓸 수 있는지 알게 됐기 때문이다. 쓸 수 없으면 묻지 말고 방식 2로 간다.

### 파악할 항목

| 항목 | 확인 방법 | 이 정보가 필요한 이유 |
|---|---|---|
| 운영체제·아키텍처 | `uname -s -m` / `$PSVersionTable` | 이후 모든 명령이 갈린다 |
| 셸 종류 | `echo $SHELL` / PowerShell 버전 | PATH 문제 진단에 쓴다 |
| uv 설치 여부 | `uv --version` | **없는 것을 기본으로 놓는다** (§4) |
| 파이썬 존재 여부 | `python3 --version` / `py --version` | 없어도 괜찮다 — uv가 직접 받아 온다 |
| VS Code 확장 목록 | `code --list-extensions` | §7에서 **빠진 것만** 권하려고 |

`code` 명령이 없다고 해서 VS Code가 없는 것은 아니다. PATH 등록 문제일 수 있다 → §9.2 참고.

## 2. 단계 1 — 과목 선택 [질문]

**질문 도구로 묻는다.** 앞의 세 개는 고정 보기, 네 번째는 주관식이다.

| 보기 | 값 |
|---|---|
| 1 | **BS** — 빅데이터통계 |
| 2 | **DM** — 데이터마이닝 |
| 3 | **FD** — 재무데이터분석 |
| 4 | **기타** — 과목 코드와 간단한 설명을 직접 적기 (예: `UD` 비정형데이터처리). 폴더 경로를 직접 적어도 됨 |

> [!warning] 이 문서는 특정 과목에 고정되어 있지 않다
> 학생이 BS 자료 폴더에서 이 문서를 열었더라도 DM을 고를 수 있다. **학생이 고른 것을 따른다.**
> 어떤 과목인지 지레짐작하지 말고 반드시 물어본다.
> **네 보기 중 어느 것도 추천으로 표시하지 않는다.** 학생이 수강하는 과목은 학생만 안다 (§0.3). 문서 뒷부분의 명령 예시에 특정 코드가 자주 나온다는 것은 추천 근거가 아니다 — 그건 그냥 예시다.

> [!important] 답 수용 규칙 — 같은 질문을 두 번 던지지 않는다
> - **과목 코드처럼 보이는 조각을 하나라도 받으면 그것으로 진행한다.** `TK`, "TK요", "4번이요 TK인데요" 는 전부 유효한 답이다
> - **설명이 없거나 "잘 몰라요" 여도 되묻지 않는다.** 설명은 패키지 제안에만 쓰이고, 없으면 공통 5개로 가면 된다 (§6.3). 그것 때문에 학생을 붙잡지 않는다
> - 코드를 대문자로 바꿔 `{CODE}_26` 폴더 이름을 만든다. 예: `ud` 라고 적었으면 `UD_26`
> - **정말로 아무 코드도 못 받았을 때만** 다시 묻는다. 이때는 같은 질문을 반복하지 말고 **"과목 이름을 줄인 알파벳 두세 글자"** 를 달라고 더 좁혀서 묻는다
> - 사과하지 않는다. "죄송해요, 다시 물어볼게요" 는 학생에게 자기가 틀렸다는 인상을 준다

**4번(기타)을 골랐을 때**:

1. 학생이 적은 코드로 폴더 경로를 제안한다 (§3의 규칙 그대로, `{CODE}_26`)
2. 학생이 적은 과목 설명을 근거로 **패키지를 제안한다** (§6)
3. 제안한 패키지가 왜 필요한지 한 줄씩 설명하고 **승인을 받는다**
4. 확신이 없으면 공통 패키지만 깔고, 나머지는 수업이 시작된 뒤 추가하자고 안내한다

## 3. 단계 2 — 폴더 위치 [질문]

### 3.1 추천 경로

| 운영체제 | 1순위 추천 |
|---|---|
| macOS | `~/Documents/Projects/{CODE}_26` |
| Windows | `C:\Projects\{CODE}_26` |

`{CODE}` 는 §2에서 학생이 고른 코드다. 예: BS를 골랐으면 `~/Documents/Projects/BS_26`.

> [!important] 왜 이 경로가 1순위인가
> **수업 자료의 모든 `cd` 명령이 이 경로를 기준으로 쓰여 있다.** 다른 경로를 고르면 앞으로 매주 나오는 명령의 경로를 학생이 직접 바꿔 가며 따라와야 한다.
> 학생이 다른 경로를 원하면 막지는 않되, **이 사실을 반드시 알려 주고** 승인을 받는다.

### 3.2 Windows 주의 (학생에게 반드시 설명)

- ❌ **바탕 화면 · 문서 · OneDrive 아래에 두지 않는다** — 동기화가 파일을 잠가서 설치가 중간에 실패한다
- ❌ **한글이나 공백이 든 경로를 쓰지 않는다** — 일부 도구가 그 경로를 못 읽는다
- ✅ `C:\Projects\` 아래로 통일한다

### 3.3 폴더 만들기

명령은 네 개다. `{CODE}` 자리에는 **§2에서 학생이 고른 코드**를 넣는다. 학생에게 명령을 줄 때는 `{CODE}` 를 이미 바꾼 상태로 준다 — 중괄호가 그대로 보이면 학생이 그걸 타이핑한다.

**macOS:**

| # | 명령 | 나와야 하는 것 |
|---|---|---|
| 1 | `pwd` | `/Users/이름` 같은 현재 위치 |
| 2 | `mkdir -p ~/Documents/Projects/{CODE}_26` | **아무것도 안 나온다** — 조용한 것이 성공이다 |
| 3 | `cd ~/Documents/Projects/{CODE}_26` | 아무것도 안 나온다 |
| 4 | `pwd` | `/Users/이름/Documents/Projects/{CODE}_26` |

**Windows PowerShell:**

| # | 명령 | 나와야 하는 것 |
|---|---|---|
| 1 | `Get-Location` | `C:\Users\이름` 같은 현재 위치 |
| 2 | `New-Item -ItemType Directory -Force -Path "C:\Projects\{CODE}_26"` | 만들어진 폴더 정보가 한 줄 |
| 3 | `Set-Location "C:\Projects\{CODE}_26"` | 아무것도 안 나온다 |
| 4 | `Get-Location` | `C:\Projects\{CODE}_26` |

**§0.4에서 정한 방식대로 진행한다.**

- **방식 1 (내가 실행)**: 네 개를 순서대로 실행하고, 마지막 `pwd` 결과가 맞는지 확인한 뒤 **"폴더를 만들고 그 안으로 들어왔습니다. 위치는 ○○입니다"** 로 보고한다. 명령을 학생에게 넘기지 않는다
- **방식 2 (학생이 직접)**: 한 줄씩 준다. 2번을 줄 때는 **"아무것도 안 나오는 게 정상"** 이라고 미리 말해 준다 — 안 그러면 학생은 실패했다고 생각한다. 매번 결과를 받고 다음 줄을 준다

4번의 출력이 예상과 다르면 **거기서 멈춘다.** 폴더 이름 오타이거나 2번이 실패한 것이다.

> [!warning] 앞으로 모든 명령은 이 폴더 안에서 실행한다
> 터미널을 새로 열면 **위치가 처음 자리로 돌아간다.** 다음 단계로 넘어가기 전에 항상 `pwd` / `Get-Location` 으로 위치를 확인한다.

## 4. 단계 3 — uv 설치

> **`uv` 가 안 깔려 있다고 가정하고 시작한다.** 단계 0에서 버전이 이미 나왔다면 이 단계는 건너뛴다.

### 4.2 설치 명령

**macOS:**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**Windows PowerShell:**

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

> 출처: [uv 공식 설치 문서](https://docs.astral.sh/uv/getting-started/installation/)

### 4.3 설치 후 — 반드시 새 터미널을 연다

> [!important] 이 단계를 건너뛰면 다음 명령이 반드시 실패한다
> 설치가 끝나면 **터미널을 완전히 닫고 새로 연다.**
> - VS Code 안에서 열었다면: 터미널 패널 오른쪽의 **휴지통 아이콘**으로 버리고 **터미널 → 새 터미널**
> - 별도 터미널 앱이라면: 창을 닫고 다시 연다
>
> 이미 열려 있던 터미널은 방금 설치된 `uv` 의 위치를 모른다. 여기서 나오는 `command not found` 는 설치 실패가 아니다.

### 4.4 확인

```bash
uv --version
```

→ **버전 번호가 나오면 성공이다** (예: `uv 0.12.7`).
→ `command not found` 또는 `'uv'은(는) ... 인식되지 않습니다` 가 나오면 §9.2로 간다.

새 터미널을 열었으므로 위치가 초기화됐다. 다음 단계로 가기 전에 다시 폴더로 이동한다.

```bash
cd ~/Documents/Projects/{CODE}_26
pwd
```

### 5.2 실행 — 반드시 위치 확인 먼저

> [!warning] `uv init` 은 **엉뚱한 폴더에서도 성공한다**
> 잘못된 자리에서 실행해도 평소와 똑같은 성공 메시지가 뜬다. 화면만 봐서는 알 수 없다.
> 그래서 **실행 전 `pwd` 한 줄이 유일한 확인 기회다.**

**macOS:**

```bash
cd ~/Documents/Projects/{CODE}_26
pwd
uv init --python 3.12
```

**Windows PowerShell:**

```powershell
Set-Location "C:\Projects\{CODE}_26"
Get-Location
uv init --python 3.12
```

`pwd` / `Get-Location` 출력이 학생의 코드 폴더가 **아니면 거기서 멈춘다.** 이동부터 다시 한다.

이미 `pyproject.toml` 이 있는 폴더라면 `error: Project is already initialized` 로 멈춘다. **이건 안전한 실패다** — 아무것도 망가지지 않았다. 학생에게 그렇게 설명하고, 기존 폴더를 쓸지 새 폴더를 만들지 물어본다. **기존 폴더를 지우지 않는다.**

### 5.3 생긴 파일 설명 (학생에게 한 문단으로)

명령 하나를 쳤는데 낯선 파일이 여러 개 생긴다. 잘못된 게 아니라 프로젝트 뼈대가 만들어진 것이다.

| 파일 | 하는 일 |
|---|---|
| `pyproject.toml` | **이 프로젝트가 쓰는 패키지 목록.** 가장 중요한 파일 |
| `.python-version` | 이 프로젝트가 쓸 파이썬 버전 (방금 고른 값) |
| `uv.lock` | 패키지의 **정확한 버전**을 고정하는 파일. `uv add` 를 하면 생긴다 |
| `.gitignore` · `README.md` · `src/` 등 | 기본 뼈대 파일. 버전에 따라 `main.py` 가 대신 생기기도 한다 |

`pyproject.toml` 은 **"무엇이 필요한가"(범위)** 를 적고, `uv.lock` 은 **"정확히 어느 버전인가"(고정)** 를 적는다. 나중에 이 폴더를 통째로 다른 컴퓨터에 옮기고 `uv sync` 한 줄을 실행하면 **똑같은 환경**이 복원된다. 그게 이 두 파일의 존재 이유다.

## 6. 단계 5 — 패키지 [질문으로 확인]

### 6.1 과목별 목록

|---|---|
| 공통 (모든 과목) | `uv add pandas numpy matplotlib seaborn ipykernel` |

- **`seaborn`** — matplotlib 위에 얹혀서 통계 그래프를 더 짧은 코드로 그린다

- **`scipy`** (BS) — 통계 검정과 확률분포 계산. t검정·카이제곱이 여기 있다
- **`statsmodels`** (BS) — 회귀분석과 시계열 모형. 계수와 p값이 붙은 요약표를 바로 내준다
- **`scikit-learn`** (DM) — 머신러닝 모형. 분류·군집·예측 모형이 여기 들어 있다
- **`finance-datareader`** (FD) — 주가·환율 같은 금융 데이터를 코드로 받아 오는 도구

### 6.3 설치 후

`.venv` 폴더가 생긴다. **이 폴더가 이 프로젝트만의 파이썬이다.** 다른 과목 패키지가 여기 안 보이는 것이 정상이고, 그게 목적이다.

`uv.lock` 파일도 함께 생겼는지 확인한다. 재현을 담당하는 파일이다.

> [!note] 기타 과목에서 패키지를 제안할 때
> 확신이 서지 않으면 **공통 5개만 깔고 멈춘다.** 필요한 패키지는 수업이 시작된 뒤 `uv add <이름>` 한 줄로 언제든 추가할 수 있다고 학생에게 알려 준다. 쓸데없는 패키지를 미리 까는 것보다 낫다.

## 8. 단계 7 — 확인 (스모크 테스트)

### 8.1 파이썬 버전 확인

```bash
uv run python --version
```

→ 단계 4에서 고른 버전이 나오면 성공이다 (예: `Python 3.12.12`).

> `uv run` 을 앞에 붙이는 이유를 학생에게 설명한다: "그냥 `python` 이라고 치면 컴퓨터에 있는 **다른** 파이썬이 실행될 수 있습니다. `uv run` 을 붙이면 방금 만든 이 폴더의 파이썬으로 돌아갑니다."

### 8.2 패키지 import 확인

**설치한 이름과 코드에서 부르는 이름이 다른 것들이 있다.** 학생이 헷갈리는 지점이므로 미리 알려 준다.

| 설치한 이름 | 코드에서 부르는 이름 |
|---|---|
| `scikit-learn` | `sklearn` |
| `finance-datareader` | `FinanceDataReader` |
| 나머지 | 이름 그대로 |

**공통 (모든 과목):**

```bash
uv run python -c "import pandas, numpy, matplotlib, seaborn, ipykernel; print('pandas', pandas.__version__); print('numpy', numpy.__version__); print('matplotlib', matplotlib.__version__); print('seaborn', seaborn.__version__); print('OK: common')"
```

**BS 추가:**

```bash
uv run python -c "import scipy, statsmodels; print('scipy', scipy.__version__); print('statsmodels', statsmodels.__version__); print('OK: BS')"
```

**DM 추가:**

```bash
uv run python -c "import sklearn; print('scikit-learn', sklearn.__version__); print('OK: DM')"
```

**FD 추가:**

```bash
uv run python -c "import FinanceDataReader; print('OK: FD')"
```

마지막 `OK:` 줄이 나오면 성공이다.
`ModuleNotFoundError` 가 나오면 그 패키지만 `uv add <이름>` 으로 다시 깐다.

### 8.3 노트북 커널 확인

> **네가 클릭할 수 없어도 이 절은 건너뛰지 않는다.** VS Code 화면 조작은 학생만 할 수 있으므로, 아래 순서를 **학생에게 말로 안내한다.** 여기가 학기 내내 가장 많이 막히는 지점이다.

패키지가 `.venv` 안에 있으므로, 노트북이 **다른 파이썬**을 가리키면 방금 깐 패키지가 하나도 안 보인다. `ModuleNotFoundError` 의 절반이 여기서 나온다.

1. VS Code에서 이 폴더를 연다 — **파일 → 폴더 열기**로 §3에서 만든 폴더를 고른다
2. 아무 `.ipynb` 파일을 열거나, 새로 만든다 (`Cmd/Ctrl+Shift+P` → `Create: New Jupyter Notebook`)
3. 노트북 **오른쪽 위의 커널 선택** 버튼을 누른다
4. **Python 환경**을 고른다
5. 목록에서 이름에 **`.venv` 가 들어간 항목**을 고른다
6. 오른쪽 위에 그 이름이 표시되는지 확인한다

| 화면에 보이는 것 | 의미 | 다음 행동 |
|---|---|---|
| `.venv` 포함된 이름 | 준비 완료 | 셀 실행 |
| 다른 Python 경로 | 엉뚱한 환경 | `.venv` 로 변경 |
| 목록에 `.venv` 없음 | 커널 등록이 안 됨 | `uv add ipykernel` 후 VS Code 재시작 |

마지막으로 첫 셀에 아래를 넣고 실행한다.

```python
import pandas as pd
print("pandas:", pd.__version__)
```

버전이 나오면 **환경 준비 완료다.**

## 9. 트러블슈팅

각 항목: **증상 → 원인 → 조치 → 그래도 안 되면 검색어**

> [!important] 먼저 확인할 두 가지
> 1. **오류 메시지의 첫 줄** (마지막 줄이 아니라 첫 줄)
> 2. **현재 폴더 경로** (`pwd` / `Get-Location`)
>
> 이 둘만 확인해도 원인의 절반이 좁혀진다. 이걸 안 보고 패키지를 다시 깔기 시작하면 같은 자리를 계속 돈다.

### 9.1 PowerShell 실행 정책 거부 (Windows)

- **증상**: `이 시스템에서 스크립트를 실행할 수 없으므로` / `running scripts is disabled on this system`
- **원인**: PowerShell이 외부 스크립트 실행을 막고 있다
- **조치**: 이 문서의 설치 명령은 이미 `-ExecutionPolicy ByPass` 를 달고 있어 대개 안 난다. 그래도 나면 현재 정책부터 확인한다.
  ```powershell
  Get-ExecutionPolicy -List
  ```
  `CurrentUser` 줄만 제한적이면 풀 수 있다.
  ```powershell
  Set-ExecutionPolicy RemoteSigned -Scope CurrentUser -Force
  ```
  `MachinePolicy` 나 `UserPolicy` 줄에 값이 잡혀 있으면 **학교·회사가 내린 정책이라 개인이 못 바꾼다.** 관리자에게 문의하라고 안내한다.
- **검색어**: `powershell set-executionpolicy currentuser remotesigned`

### 9.2 `uv: command not found` / `'uv'은(는) 인식되지 않습니다`

- **증상**: 설치는 성공 메시지가 떴는데 `uv --version` 이 실패
- **원인**: **설치 실패가 아니다.** 지금 열려 있는 터미널이 새로 깔린 도구의 위치를 아직 모르는 것이다 (PATH 미등록)
- **조치**:
  1. 터미널을 **완전히 닫고** 새로 연다. 탭만 새로 여는 건 부족할 수 있다
  2. 그래도 안 되면 **재부팅**한다 (Windows에서 특히 효과적)
  3. macOS에서 계속 실패하면 설치 위치를 직접 확인한다
     ```bash
     ls -l ~/.local/bin/uv
     ```
     파일이 있으면 설치는 된 것이다. `~/.local/bin` 이 PATH에 없는 상태다
- **같은 원인의 다른 증상**: `code: command not found`. VS Code가 없는 게 아니라 PATH 등록이 안 된 것이다.
  macOS는 VS Code에서 `Cmd+Shift+P` → `shell command` 입력 → **Shell Command: Install 'code' command in PATH** 를 실행한 뒤 터미널을 새로 연다.
  Windows는 재부팅하거나, 설치 마법사의 **Add to PATH** 를 체크하고 다시 설치한다.
- **검색어**: macOS `add ~/.local/bin to PATH zsh` / Windows `uv not recognized windows path`

### 9.3 한글·공백·OneDrive 경로에서 설치 실패 (Windows)

- **증상**: 설치 중 파일 잠금·권한 오류, 또는 `uv add` 가 중간에 멈춤
- **원인**: OneDrive가 폴더를 실시간 동기화하면서 파일을 잠근다. 한글·공백 경로는 일부 도구가 못 읽는다
- **조치**: 코드 폴더를 `C:\Projects\{CODE}_26` 로 **새로 만들고** 거기서 §5부터 다시 시작한다.
  **기존 폴더는 지우지 않는다.** 그냥 두고 새 폴더를 쓴다
- **검색어**: `onedrive python venv file lock error`

### 9.4 학교·회사 네트워크의 프록시·SSL 인증서 오류

- **증상**: `SSL: CERTIFICATE_VERIFY_FAILED`, `unable to get local issuer certificate`, 다운로드가 계속 실패
- **원인**: 기관 네트워크가 트래픽을 중간에서 검사하면서 자체 인증서를 끼워 넣는다
- **조치**:
  1. **먼저 다른 네트워크에서 시도한다** — 휴대폰 테더링이나 집 와이파이. 이게 가장 빠른 해결이다
  2. 그래도 필요하면 기관 인증서 경로를 환경변수로 지정한다 (**학교 IT에서 받은 인증서 파일이 있을 때만**)
     ```bash
     export SSL_CERT_FILE=/받은/경로/기관인증서.pem
     ```
  3. **인증서 검증을 끄는 방법은 안내하지 않는다.** 보안을 낮추는 조치이므로 학생에게 권하지 않는다
- **검색어**: `uv ssl certificate verify failed corporate proxy`

### 9.5 `winget` 이 없다 (Windows)

- **증상**: `winget` 명령을 못 찾는다
- **원인**: 구형 Windows 10에는 기본 탑재가 아니다
- **조치**: **이 문서의 절차는 `winget` 을 쓰지 않는다.** §4.2의 PowerShell 설치 명령을 그대로 쓰면 된다.
  다른 안내에서 `winget` 을 봤다면 그건 이 문서의 경로가 아니라고 학생에게 알려 준다
- **검색어**: `install app installer microsoft store winget`

### 9.6 Windows 긴 경로 제한

- **증상**: `파일 이름이 너무 깁니다`, `The specified path, file name, or both are too long`
- **원인**: Windows가 기본적으로 260자 경로 제한을 건다. 패키지 폴더는 경로가 깊어진다
- **조치**:
  1. **가장 빠른 해결은 폴더를 얕게 옮기는 것이다** — `C:\Projects\{CODE}_26` 로 옮기면 대개 해결된다
  2. 그래도 나면 긴 경로 지원을 켠다. **관리자 권한 PowerShell**에서 실행한다 (여는 법은 §0.5, 제목 표시줄에 "관리자"가 보여야 한다):
     ```powershell
     Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name "LongPathsEnabled" -Value 1
     ```
     실행 후 재부팅한다. **이건 시스템 설정 변경이므로 학생에게 설명하고 승인을 받은 뒤에 안내한다**
- **검색어**: `windows enable long paths python`

### 9.7 macOS에서 `curl` 설치가 조용히 실패할 때

- **증상**: 설치 명령을 실행했는데 아무 메시지도 없이 끝나고, `uv --version` 도 안 된다
- **원인**: 파이프(`| sh`)로 넘기면 다운로드 실패 메시지가 묻힌다
- **조치**: 파이프를 빼고 다운로드만 먼저 해 본다
  ```bash
  curl -LsSf https://astral.sh/uv/install.sh -o ~/Downloads/uv-install.sh
  ls -l ~/Downloads/uv-install.sh
  ```
  - 파일 크기가 **0이거나 파일이 없으면** 네트워크·프록시 문제다 → §9.4
  - 파일이 정상이면 실행한다
    ```bash
    sh ~/Downloads/uv-install.sh
    ```
- **검색어**: `curl silent failure proxy macos`

### 9.8 노트북에서 `ModuleNotFoundError`

- **증상**: 터미널에서는 되는데 노트북에서만 패키지를 못 찾는다
- **원인**: 노트북 커널이 `.venv` 가 아닌 다른 파이썬을 가리키고 있다
- **조치**: §8.3의 커널 선택 절차를 다시 한다. 목록에 `.venv` 가 없으면 `uv add ipykernel` 후 VS Code 재시작
- **검색어**: `vscode jupyter select kernel venv not showing`

## 10. 마지막 — 학생에게 남기는 요약

**이 절은 선택이 아니다.** 앞 단계가 전부 끝났으면 반드시 아래 형식으로 **한 번에 정리해 주고 대화를 마친다.** 학생이 나중에 다시 볼 수 있게, 복사해서 보관하라고 알려 준다.

중간에 멈춘 경우에도 **거기까지의 상태로 요약을 준다.** 못 끝낸 항목은 "미완료 — §N부터 이어서"로 적는다. 요약 없이 끝나는 경우는 없다.

```text
=== 수업 환경 준비 완료 ===

과목:          BS (빅데이터통계)
폴더 경로:     /Users/이름/Documents/Projects/BS_26
파이썬 버전:   3.12.12
설치한 패키지: pandas, numpy, matplotlib, seaborn, ipykernel, scipy, statsmodels
설치한 확장:   ms-python.python, ms-toolsai.jupyter, pkief.material-icon-theme,
              usernamehw.errorlens

--- 다음에 이 폴더로 돌아오는 법 ---
1. 터미널을 연다
2. cd ~/Documents/Projects/{CODE}_26     ← Windows는 Set-Location "C:\Projects\{CODE}_26"
3. pwd 로 위치가 맞는지 확인
4. 코드 실행은 항상 uv run 을 앞에 붙인다   (예: uv run python main.py)

--- 알아 두면 좋은 명령 네 개 ---
uv init          프로젝트 시작할 때 딱 한 번
uv add <이름>    새 패키지가 필요할 때마다
uv run <명령>    코드를 돌릴 때마다
uv sync          다른 컴퓨터에서 이 폴더를 열었을 때 환경 복원
```

위 값은 **실제로 실행한 결과로 채운다.** 추정해서 채우지 않는다 — 확인하지 못한 항목은 "확인 필요"로 남긴다.

## 11. 하다 만 걸 이어서 할 때 · 이 문서를 어디 두는지

### 11.1 이어서 할 때 — 폴더를 보고 판정한다

학생이 "전에 하다 말았어요", "어제 하다가 껐어요" 라고 하면 **처음부터 다시 시키지 않는다.** 어디까지 갔는지는 **폴더가 이미 알고 있다.**

먼저 과목 코드를 물어 폴더 경로를 정한 뒤, 그 폴더 안을 본다.

```bash
ls -a ~/Documents/Projects/{CODE}_26
```
(Windows: `Get-ChildItem -Force "C:\Projects\{CODE}_26"`)

`{CODE}` 자리에는 학생이 고른 과목 코드를 넣는다. 이 문서 어디에도 실제 코드를 박아 두지 않는다.

| 보이는 것 | 여기까지 왔다 | 이어서 할 곳 |
|---|---|---|
| 폴더 자체가 없다 | 아무것도 안 됨 | §3 (폴더 만들기) |
| 폴더는 있는데 비어 있다 | 폴더까지 | §5 (파이썬 버전 · `uv init`) |
| `pyproject.toml` · `.python-version` 있음 | 뼈대까지 | §6 (패키지) |
| `uv.lock` · `.venv` 있음 | 설치까지 | §8 (확인) |
| §8의 확인 명령이 통과 | 사실상 끝 | §7 (확장) 확인 후 §10 요약 |

> [!important] 진행 상태를 적은 파일을 따로 만들지 않는다
> 폴더 내용이 곧 진행 상태다. 별도 기록 파일은 같은 정보를 한 벌 더 적는 것이고, 학생이 중간에 직접 뭔가 하면 **그 파일만 사실과 어긋난다.** 폴더는 어긋날 수 없다.
> `.python-version` 은 학생이 고른 파이썬 버전을, `pyproject.toml` 의 `dependencies` 는 깔린 패키지를 그대로 담고 있으니 **읽어서 §10 요약을 채우면 된다.** 추정하지 않는다.

이어서 할 때도 **단계 0(환경 파악)은 다시 한다.** 새 컴퓨터일 수도 있고, 그 사이에 뭔가 바뀌었을 수도 있다. 읽기만 하므로 비용이 거의 없다.

### 11.2 이 문서를 어디 두는지

**시작할 때는 받은 자리 그대로 둔다.** 보통 `~/Downloads` 다.

- 이 문서는 자기 위치에 의존하지 않는다. 학생은 **"다운로드에 있는 이 파일대로 해줘"** 한 줄이면 된다
- 시작 시점에 `~/Documents/Projects/` 가 있다고 전제할 수 없다. **그 폴더를 만드는 것이 이 문서가 하는 일이기 때문이다**
- 파일을 첨부하는 방식의 런타임(Copilot Chat 등)이라면 위치는 아예 상관없다

**끝나고 나면 옮겨 둔다.** §10 요약을 준 뒤, 마지막으로 학생에게 제안하고 승인을 받는다.

```bash
mv ~/Downloads/<이 문서 파일명> ~/Documents/Projects/
```
(Windows: `Move-Item "$HOME\Downloads\<파일명>" "C:\Projects\"`)

과목 폴더들 **옆**에 두는 것이지 안에 넣는 것이 아니다. 다음 학기에 다른 과목을 들을 때 같은 자리에서 다시 쓰기 위해서다. **이 문서는 과목에 매여 있지 않으므로 과목 폴더 안에 두면 안 된다.**

학생이 옮기기를 원하지 않으면 그냥 둔다. 대신 **"나중에 다른 과목 들을 때 이 파일 또 쓰시면 됩니다"** 라고 알려 준다.
